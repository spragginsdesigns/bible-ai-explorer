Model recommendation: evaluate gpt-5.6-luna at high reasoning for normal questions on both tiers. Keep tiny utility calls and tap-a-verse responses at lower effort when that improves latency without harming quality; do not silently change the advertised primary model.

Counting: one user request counts once, including its tools, title and memory work. New regeneration counts; automatic retry of the same request does not. Notes AI, fresh verse explanations, and generated reading plans share the allowance; cached reopens and ordinary reading do not.

Reset: launch with a fixed midnight UTC day, displayed in each user's local time, and a billing-period quota for Pro. This avoids device clock and timezone switching bypasses; the API returns remaining and resetAt.

Fees, subsidy and break-even sensitivity

US domestic card assumption: $10 less 2.9% + $0.30 Payments and 0.7% Billing = $9.34. Google Play auto-renewing subscription fee assumption: 15%, leaving $8.50 before other costs; Apple fees need verification for the actual program and storefront. Payments pricing · Billing pricing · Play fees

At 600 planning-case actions, $9.34 − $4.08 − an illustrative $1 reserve = $4.26 contribution per web subscriber before subsidizing Free and fixed overhead. That supports about two Free users consuming every daily allowance, or about ten Free users making 60 actions/month; these are break-even illustrations, not profit targets.

For 1,000 monthly active users at 5% paid: 50 × $9.34 = $467 receipts. With paid users at 600 actions and 950 Free users at 60 actions, model cost is $204 + $387.60 = $591.60, already a $124.60 loss before hosting, search, audio, tax tooling, refunds and support.

If the same 950 Free users average 20 actions, model cost becomes $333.20, leaving $133.80 before those costs. Measure actual actions per active free user and paid conversion together; a low token price alone does not prove the business.

Rollout budget proposal: cap the initial acquisition cohort at 100 active Free users and review a $300 monthly free-service budget, rather than quietly shortening their promised daily allowance. At the planning case and a 30-day month, their maximum main-model cost is $204; $300 is a planning budget, not a verified total-cost ceiling.

One enforcement path: authenticate → resolve grants/subscription and explicit payer → atomically reserve daily/monthly allowance and bounded cost → run within aggregate token/tool/time budget → persist result → settle usage. Both web and native clients use this path; a forged model, effort, plan or user ID must not raise company spending.

Use transactional conditional updates or row locks and uniqueness constraints in the existing database. A plain count-then-insert races; an in-memory limiter resets across instances. Track abandoned reservations and reconcile interrupted requests with a lease and provider/result evidence before releasing them.

Persisted completed answers count even if the client disconnects. Genuine failed or empty answers release the message allowance while actual provider spend remains recorded; uncertain outcomes keep a reservation until reconciled, and repeated failures still face an abuse limit.

Design decision

Add an explicit choice between Included AI and Personal API key for users who saved keys; currently merely saving a key changes the account's entire AI path. Never silently fall back from an exhausted personal key to company funding, and never charge a personal key because the user clicked the included option.

Owner identity and indirect costs

Resolve Austin's supplied email through the verified Clerk identity once and bind an audited owner grant to that immutable user ID. Do not authorize from browser-supplied email, substring matching or editable profile metadata; webhook downgrades must never remove owner access, and an owner grant does not grant access to other users' private content.

Keep personal keys encrypted and masked. BYOK AI does not consume included-message counts, but uploads, search, speech, storage and shared utility services still need independent limits; label which services SureWord funds.

Cover ask-question, note-ai, verse-insight, note composition, generated reading plans, suggestions, memory summaries, memory extraction, titles, church generation, progress narration, Daily Cross and audio. Cache shared public outputs where valid; per-user private or church content must remain isolated.

Set maximum aggregate context, output including reasoning, tool steps, retries, attachment size and concurrent runs. Reserve budget before each paid step, including utility calls; prevent compaction or fallback from moving spend outside the ledger. Keep prompt contents, notes, religious disclosures and keys out of billing analytics.

Acceptance and rollback gates
  • A new verified user gets a useful first answer without a card, key or model decision.
  • The eleventh Free action is denied consistently across browser tabs, servers, Android and Apple clients; tool calls do not consume extra user messages.
  • Pro period renewal, day/month boundaries, payment recovery, cancellation, refunds, duplicate and delayed webhooks produce the correct allowance.
  • Saving or deleting a BYOK key does not hide purchased included usage or silently switch who pays; owner privileges survive plan changes.
  • Every company-paid service is accounted for, including failed attempts, disconnected streams and background work.
  • Answer review covers Scripture accuracy, contextual relevance, pastoral tone, denominational differences and translation-preserving citations, with no critical invented quotation or attribution.
  • Public signup and pricing work at desktop and phone widths; paid access restoration is tested on each released client.
  • Disable new Checkout or new Free cohort admission independently if needed, keep webhook reconciliation running, and preserve existing paid access and saved data. Emergency inference interruption is a disclosed incident, not an undisclosed pricing rule.
