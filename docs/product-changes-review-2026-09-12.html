Two shared files need a contract before two lanes touch them. Fable publishes both in Stage 0: the receipt shape on a chat message (one receipts array with kind, label, target) that Codex renders, and the learn-a-verse API (queue, review, progress) that Kimi builds against.

Rules for every lane

  1. Work on a branch, not on main. codex/<item>, kimi/<item>. Main auto-deploys to sureword.app and the Android app calls it, so a half-done lane on main is a live outage. Fable merges branches after review and proof; Vercel preview URLs are the review surface for web.
  2. Prove on the real product path before calling anything done. Android emulator or device first (docs/android-emulator-proof-recipe in memory), then web in a browser at desktop and 375px. Static checks are support only: pnpm lint && pnpm build for web, cd mobile && npm run typecheck && npm test for Android. Screenshots go in artifacts/<item>/.
  3. Capability parity in the same cycle. Whatever ships on Android ships on web in the same branch. macOS and iOS cannot be built on this PC: update docs/PARITY.md with the exact gate and never mark Apple verified.
  4. Touched files only. Conventional Commits, never git add -A, never commit mobile/.phone-addr or secrets. Nobody but Fable runs push-phone.sh, bumps mobile/app.json, or writes mobile/CHANGELOG.md; Android releases are batched per stage.
  5. No new dependency, migration, or tool without asking Fable. The model already juggles 24 tools; migrations go through prisma migrate deploy against production by Fable only.
  6. Return format for every finished item: branch name, files changed, the commands run with real output, proof screenshots, open risks. Never "tests pass" alone.
