# SureWord for Windows

SureWord Windows Phase 1 is a PWABuilder Hosted App package generated from
`https://sureword.app`. The package is an MSIX wrapper around the deployed web
app, so web releases provide the application content and parity. There is no
native Windows source in this directory.

## Current readiness

PWABuilder's live report card accepted the production manifest with zero
required issues and enabled Windows test-package generation. Its report card
did not detect a service worker. The production endpoint is nevertheless live:
`GET https://sureword.app/sw.js` returned HTTP 200 with JavaScript content on
2026-09-12. Treat service-worker detection as an open PWABuilder validation
issue until the report card recognizes it. The source configuration that
generates it is `next.config.mjs`, where `next-pwa` writes to `public` and
registers the worker.

The manifest contract is in `public/site.webmanifest`: name and short name are
`SureWord`, `start_url` and scope are `/`, display is `standalone`, and the
192x192 and 512x512 `any` and maskable icons are present. The icon files are
generated by `scripts/apply-logo.py`; do not hand-edit or redraw them.

## Reproduce a local test install

These steps require a deployed `https://sureword.app` and the PWABuilder web
UI. Do not commit the downloaded package or certificate material.

1. Open [PWABuilder](https://www.pwabuilder.com), enter
   `https://sureword.app`, and run the report card.
2. Choose the Windows test-package action and download the ZIP.
3. Extract the ZIP into a local directory. The generated package contains:
   `SureWord.sideload.msix`, `SureWord.msixbundle`,
   `SureWord.classic.appxbundle`, `install.ps1`, and
   `utils/pwainstaller.exe`.
4. From the extracted directory, run the generated installer:

   ```powershell
   .\install.ps1
   ```

   `install.ps1` checks that Windows is at least `10.0.19041`, invokes
   `utils/pwainstaller.exe` against `SureWord.sideload.msix`, then resolves the
   `SureWord` Start-menu entry and launches `shell:AppsFolder\<AppId>`. The
   generated installer does not import a certificate and does not change the
   PowerShell execution policy.

5. Verify the install and launch from PowerShell:

   ```powershell
   Get-AppxPackage -Name 'MyCompany.SureWord'
   Get-StartApps -Name 'SureWord'
   ```

   The verified test package installed as
   `MyCompany.SureWord_1.0.1.0_neutral__9k1q23xvwp0mc`, with package status 0,
   and `Get-StartApps` mapped `SureWord` to
   `MyCompany.SureWord_9k1q23xvwp0mc!App`. The installer process returned exit
   code 0. The verified sideload package SHA-256 is:

   ```text
   9A771D302ED967ED5F946E5D9D71103C9DC4DF9DE79BC5D6A2E820D3D6D11C00
   ```

The verified package used PWABuilder's placeholder identity `MyCompany.SureWord`
and `My Company Inc`. It is a local test receipt only, not a Store-ready
identity. The Start-menu and process checks passed. A screenshot and signed-in
runtime proof remain outstanding because native UI automation is unavailable in
this environment.

## Store package and identity contract

Before generating the Store package, enroll the Microsoft account in the
Windows Developer Program and reserve `SureWord` in Partner Center. From
Product management > Product Identity, copy the exact, case-sensitive:

- Package ID
- Publisher ID
- Publisher display name

Enter all three values in PWABuilder's Windows package options. The reserved
display name must match the package display name. A mismatch causes Partner
Center identity or unreserved-name errors.

For a new Store submission, upload both `SureWord.msixbundle` and
`SureWord.classic.appxbundle`. The modern package targets Windows
`10.0.19041` and later; the classic package covers older supported Windows
versions with reduced Hosted App integration. Do not upload
`SureWord.sideload.msix`; PWABuilder documents that Partner Center rejects the
sideload package. Select Windows 10 Desktop in the supported platforms list.

Microsoft re-signs MSIX and AppX packages during Store publishing, so a CA
code-signing purchase is not required for this Store route. Local sideload
testing uses the package and installer generated by PWABuilder. Direct
distribution outside the Store is a different path and requires publisher
certificate trust on target machines.

Web content updates normally arrive from `sureword.app` without a new Store
submission. Changes to the web manifest, such as the app name, icon, or added
manifest members, require a new package and Store submission.
